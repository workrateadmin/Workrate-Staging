WORKRATE — FINISH VAPI PHONE INTEGRATION

GOAL:
Complete the Vapi → WorkRate integration so a finished phone call automatically creates or updates the correct WorkRate enquiry.

IMPORTANT:
Do NOT redesign the enquiry system.
Do NOT hardcode Huntley Bespoke.
This must be multi-tenant from day one.
Do NOT change the working Vapi assistant unless required for integration.

==================================================
1. INSPECT CURRENT STATE
==================================================

First inspect:

- existing Vapi integration code
- webhook routes
- enquiry schema
- channel handling
- company/integration mapping
- customer matching logic
- transcript / activity storage
- existing phone-related work already completed

Report briefly what already exists and what is genuinely missing.

Then implement only the missing pieces.

==================================================
2. VAPI WEBHOOK
==================================================

Create or finish the secure Vapi webhook endpoint.

Example:
POST /api/webhooks/vapi

Handle the relevant Vapi call events, especially final/end-of-call events.

Validate webhook authenticity using Vapi's current supported server authentication/signature method.

Do not accept arbitrary unauthenticated payloads.

==================================================
3. MULTI-TENANT BUSINESS RESOLUTION
==================================================

Map each Vapi assistant / phone number to one WorkRate business.

Support fields such as:

- WorkRate business/company ID
- Vapi assistant ID
- Vapi phone number ID
- phone number
- enabled status

Never globally assume Huntley Bespoke.

Future WorkRate customers must be connectable without code changes.

==================================================
4. STORE CALL DATA
==================================================

For each completed call store, where available:

- Vapi call ID
- WorkRate business ID
- caller phone number
- assistant ID
- phone number ID
- call start
- call end
- duration
- transcript
- Vapi summary
- recording URL if enabled
- call status
- ended/disconnect reason

Preserve the raw transcript.

Make processing idempotent:
Vapi retries must not create duplicate call records or enquiries.

==================================================
5. CREATE / UPDATE ENQUIRY
==================================================

Use the EXISTING WorkRate enquiry system.

Do not build a separate phone CRM.

For a genuine new caller:
- create one enquiry
- channel = phone
- save caller number
- populate only information supported by the transcript

Extract where available:

- customer name
- phone
- email
- project/job type
- description
- postcode/location
- measurements
- timing
- budget
- useful requirements

Do not invent missing values.

For an existing caller:
- match sensibly by phone number and current/relevant enquiry
- update/link rather than creating unnecessary duplicates

Do not combine clearly unrelated jobs solely because the phone number matches.

Use the transcript as evidence.

7. WORKRATE DASHBOARD
==================================================

Phone enquiries should appear in the normal enquiry dashboard.

Show:
Channel: Phone

On enquiry detail show:

- call date/time
- caller number
- duration
- call summary
- transcript
- recording link if available
- call status

Do not create a separate phone-only dashboard.

==================================================
8. SAME CUSTOMER TIMELINE
==================================================

Phone activity must feed the same WorkRate customer/enquiry history used by:

- website enquiries
- WhatsApp
- email
- manual enquiries

Phone must not become a silo.

==================================================
