WORKRATE — TASK #99
CATCH INCORRECT STORAGE / BUCKET CONFIGURATION BEFORE RELEASES GO LIVE

GOAL:

Prevent development, staging, or production from ever being deployed with the wrong storage bucket, wrong environment marker, wrong storage identity, or unsafe legacy-path compatibility.

The system must fail BEFORE release goes live if storage configuration does not match the intended WorkRate environment.

IMPORTANT:

Task #97 is complete and must be preserved.

Existing protections include:

- Environment-prefixed object paths
- Dev/staging rejection of production, cross-environment, malformed, and legacy-unprefixed paths
- Production-only compatibility for legacy unprefixed reads
- Immutable bucket environment marker checked before API startup
- Bucket identity fingerprint and binding status in owner diagnostics
- Development bucket initialized and verified
- Environment-aware WhatsApp storage URLs

Do NOT weaken these controls.
Do NOT mutate production storage.
Do NOT publish automatically.

==================================================
1. AUDIT CURRENT RELEASE-TIME STORAGE CHECKS
==================================================

Inspect:

- startup storage guard
- bucket marker validation
- bucket fingerprint/binding logic
- WORKRATE_ENV
- staging/production deployment config
- release scripts/runbooks
- diagnostics
- build/deploy hooks available in Replit

Identify which storage mistakes are currently detected only AFTER deployment/startup rather than BEFORE release promotion.

==================================================
2. CREATE A PRE-RELEASE STORAGE VALIDATOR
==================================================

Add a reusable pre-release command/script.

Suggested command:

pnpm verify:release-storage

or equivalent.

Inputs should come only from trusted environment configuration.

Validate:

- WORKRATE_ENV is valid
- configured bucket exists
- bucket environment marker exists
- marker matches WORKRATE_ENV
- bucket identity fingerprint matches configured expected identity where required
- storage namespace matches environment
- production compatibility mode is disabled outside production
- dev/staging cannot resolve production namespace
- staging cannot resolve development namespace
- production cannot accidentally target staging/development bucket
- required storage credentials are present
- storage credentials can access ONLY the expected bucket/resources where technically verifiable

Fail non-zero on any mismatch.

==================================================
3. FAIL CLOSED
==================================================

Release validation must hard fail for:

development + production bucket
staging + production bucket
production + staging bucket
production + development bucket
missing bucket marker
invalid marker
unexpected bucket fingerprint
legacy compatibility enabled outside production
unknown environment
malformed namespace
unverified binding

Do not downgrade these to warnings.
